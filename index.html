Overview

admin01@helpdesk1:~/lab2$ cat README

A self-hosted IT help desk built on a Linux server and run like a small company's support team. Users submit tickets through a portal; help topics route each ticket to the right team with the right priority and SLA; a Tier 1 technician works account issues and escalates anything that needs authorization to Tier 2; recurring fixes are written up as knowledge base articles and canned responses.

It builds directly on the Active Directory lab: the server resolves names through the domain controller, osTicket connects to AD with a least-privilege service account, and the tickets worked here are the same account problems practiced in Lab 1.

Phase 1
Build: Ubuntu Server VM, LAMP stack, osTicket install and lockdown
Phase 2
Configure: SLAs, departments, help topics, roles, AD integration, user accounts
Phase 3
Operate: tickets, Tier 1 to Tier 2 escalation, knowledge base, canned responses
Skills
Linux administration, SSH, Apache, MariaDB, LDAP, ITSM workflow, SLA management, documentation

Phase 1: Build

admin01@helpdesk1:~/lab2$ history | grep phase1

[1/6]Create the VM JARVIS, PowerShell

Generation 2 VM, 2 vCPUs, 2 GB RAM, 25 GB disk on LabSwitch. Hyper-V's default Secure Boot template only trusts Windows, so it was switched to the UEFI CA template before first boot.

Set-VMFirmware -VMName HELPDESK1 -SecureBootTemplate MicrosoftUEFICertificateAuthority
Set-VMProcessor -VMName HELPDESK1 -Count 2

[2/6]Install Ubuntu Server 24.04 LTS

Static IP, DC01 as DNS server, emillab.local search domain, hostname helpdesk1 to match the VM name, OpenSSH enabled. An A record was added on DC01 so clients can reach it by name, and everything after this point was done over SSH.

# DC01
Add-DnsServerResourceRecordA -ZoneName "emillab.local" -Name "helpdesk1" -IPv4Address "192.168.50.20"
# JARVIS
ssh admin01@192.168.50.20

[3/6]Post-install: disk, time zone, LAMP stack

The installer only allocated 10.7 GB of the 25 GB disk to the root volume, so the LVM volume was extended. Time zone set to Central so ticket timestamps are correct.

sudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv
sudo timedatectl set-timezone America/Chicago
sudo apt update && sudo apt upgrade -y
sudo apt install -y apache2 mariadb-server php php-mysql php-imap php-gd php-intl php-apcu php-mbstring php-xml php-curl php-ldap unzip
php -v    # PHP 8.3.6
systemctl is-active apache2 mariadb

[4/6]Secure MariaDB and create a least-privilege database account

osTicket gets its own database user that can only see its own database, not the root account.

sudo mysql_secure_installation
sudo mysql
CREATE DATABASE osticket;
CREATE USER 'osticket'@'localhost' IDENTIFIED BY '********';
GRANT ALL PRIVILEGES ON osticket.* TO 'osticket'@'localhost';
FLUSH PRIVILEGES;
mysql -u osticket -p -e "SHOW DATABASES;"   # only information_schema and osticket

[5/6]Deploy osTicket and an Apache virtual host

cd /tmp
wget https://github.com/osTicket/osTicket/releases/download/v1.18.4/osTicket-v1.18.4.zip
unzip -q osTicket-v1.18.4.zip -d osticket
sudo mkdir -p /var/www/osticket
sudo cp -r osticket/upload/* /var/www/osticket/
sudo cp /var/www/osticket/include/ost-sampleconfig.php /var/www/osticket/include/ost-config.php
sudo chown -R www-data:www-data /var/www/osticket
# /etc/apache2/sites-available/osticket.conf
<VirtualHost *:80>
    ServerName helpdesk1.emillab.local
    DocumentRoot /var/www/osticket
    <Directory /var/www/osticket>
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
sudo a2ensite osticket.conf
sudo a2dissite 000-default.conf
sudo a2enmod rewrite
sudo apache2ctl configtest   # Syntax OK
sudo systemctl restart apache2

[6/6]Run the web installer, then lock it down

All prerequisites passed on PHP 8.3.6. After install, the config file (which holds the database password) was made read-only and the setup folder removed so the installer can't be re-run.

sudo chmod 0644 /var/www/osticket/include/ost-config.php
sudo rm -rf /var/www/osticket/setup

SLA plans

Four response tiers. P3 is the default, and the built-in Default SLA was disabled so it can't be picked by mistake.

PlanGrace periodUsed for
P1 - Critical4 hoursOutages, many users affected
P2 - High8 hoursOne user can't work (lockouts, disabled accounts)
P3 - Normal24 hoursStandard requests (default)
P4 - Low72 hoursQuestions and minor requests

Departments and help topics

Two departments form the escalation path: IT Help Desk (Tier 1) and Systems Administration (Tier 2). Each help topic sets the department, priority and SLA automatically, so tickets route themselves. A department's SLA is only a fallback; the topic's SLA wins.

Active Directory integration

osTicket reads the directory through a dedicated, non-admin service account instead of an admin login. Connectivity and credentials were proven with ldapsearch directly from the server before touching the plugin, so any later failure could be isolated to osTicket's settings.

# DC01
New-ADOrganizationalUnit -Name "Service Accounts"
New-ADUser -Name "svc-osticket" -SamAccountName svc-osticket -UserPrincipalName "svc-osticket@emillab.local" `
  -Path "OU=Service Accounts,DC=emillab,DC=local" -AccountPassword (Read-Host -AsSecureString "Password") `
  -Enabled $true -PasswordNeverExpires $true -CannotChangePassword $true -Description "osTicket LDAP lookup - read only"
Set-ADUser jdoe -EmailAddress "jdoe@emillab.local"   # repeated for jsmith, pparker
sudo apt install -y ldap-utils
ldapsearch -x -H ldap://dc01.emillab.local -D "svc-osticket@emillab.local" -W \
  -b "DC=emillab,DC=local" "(sAMAccountName=jdoe)" cn mail
dn: CN=Jane Doe,OU=Lab Users,DC=emillab,DC=local
cn: Jane Doe
mail: jdoe@emillab.local
result: 0 Success

The LDAP and Active Directory plugin was installed with the domain, DC, service account, search base and Microsoft AD schema, with staff and client authentication enabled. End-user portal accounts were ultimately registered locally rather than bound to AD (see known issues).

Ticket workflow

Every ticket followed the same routine: claim it, record what was checked and changed in an internal note (never visible to the user), then send a plain-language reply and set the status. Passwords were never written in a ticket.

Escalation: #342101 "Account says disabled"

Tier 1 confirmed the account was disabled in AD but did not re-enable it, because a disabled account can be intentional (offboarding or a security hold). Tony noted the finding, transferred the ticket to Systems Administration and told the user it had been escalated. The ticket left Tier 1's queue; Tier 2 confirmed the account had been disabled in error, re-enabled it with Enable-ADAccount jsmith, replied, and closed it as Resolved.

# Real problems hit during the build: symptom, root cause, fix

Temporary failure resolving 'archive.ubuntu.com'

Ubuntu installer mirror test

SymptomThe installer could not reach the package mirror.
CauseThe VM's only DNS server is DC01, and DC01 was powered off.
FixStarted DC01 first. This set the lab's boot order: DC01, wait for AD and DNS, then HELPDESK1, then CLIENT01. Shutdown is the reverse.

Wrong release: package lists showed "resolute"

Same screenshot, different problem

SymptomThe mirror output referenced resolute, the codename for Ubuntu 26.04, not 24.04.
CauseThe newest ISO had been downloaded. Its newer PHP wasn't confirmed as supported by osTicket 1.18.
FixRebuilt on Ubuntu 24.04.5 LTS, which ships PHP 8.3; the osTicket prerequisite check later passed with every item green.

>>Start PXE over IPv4.

First boot of the new VM

SymptomThe VM skipped the DVD and tried to boot from the network.
CauseThe VM wasn't booting the Ubuntu ISO: Secure Boot template, ISO attachment and boot order all needed checking for a Linux guest.
FixConfirmed the Microsoft UEFI Certificate Authority template, the 24.04 ISO in the DVD drive, and DVD first in the firmware boot order.

The Virtual Machine Management service is not available

Hyper-V Manager on the host

SymptomEvery VM disappeared from Hyper-V Manager; the service sat in StopPending and refused to start.
Cause"Stop Service" was clicked by accident (it sits next to "Remove Server").
FixWaited for the service to finish stopping, then Start-Service vmms. VMs and checkpoints were unaffected; only the management service had stopped.

Permission denied (publickey,password)

ssh admin1@192.168.50.20

CauseWrong username: the account was admin01. SSH and the network were fine; the error only means the credentials didn't match.
FixConfirmed the exact name at the console, then ssh admin01@192.168.50.20.

Root filesystem only 10.70 GB on a 25 GB disk

SSH login banner

CauseThe Ubuntu installer's default LVM layout leaves free space unallocated.
Fixsudo lvextend -r -l +100%FREE /dev/ubuntu-vg/ubuntu-lv grew the volume and filesystem in one step.

ERROR 1396 (HY000): Operation CREATE USER failed

MariaDB

CauseThe first CREATE USER had already run with the example placeholder password, so the second attempt found the user existing.
FixChanged it with ALTER USER. The first attempt from the shell then failed with -bash: !': event not found, because bash expands ! inside double quotes; running ALTER USER inside the MariaDB shell avoided it.

Sudo is disabled on this machine

sudo mysql

CauseThe SSH session had closed and the command ran in a local Windows PowerShell window instead of on the server.
FixReconnected over SSH. Habit: check the prompt (admin01@helpdesk1 vs PS C:\) before running anything.

Account confirmation required / Access denied

Portal sign-in as jdoe

SymptomValid sign-ins were refused, then the session hit "maximum failed login attempts."
CauseThree things stacked up: the plugin's staff and client authentication boxes were unchecked; an earlier "Create an account" attempt left a local account stuck in Locked (Pending Activation), waiting for an email the lab can't send; and the password being typed was wrong.
FixBypassed osTicket and tested the credentials directly with ldapsearch -D "jdoe@emillab.local", which returned data 52e (bad password). Reset the AD password, confirmed result: 0 Success, enabled both authentication modes, deleted the stuck record and re-registered the user from the agent side with no activation email.

Usernames vanished from KB commands

Internal procedure article

CauseThe article's rich-text editor treated the <user> placeholder as an HTML tag and deleted it, leaving commands like Unlock-ADAccount with no argument.
FixReplaced the placeholder with USERNAME and rebuilt each code block.

Known issues and future work

admin01@helpdesk1:~/lab2$ cat KNOWN_ISSUES

Portal users use local osTicket accounts, not AD sign-in

The LDAP plugin is installed and its service account is verified, but binding end-user accounts to the AD backend wasn't reliable in this build, so users were registered with local accounts and a forced password change at first sign-in. Next step: register users against the AD backend and confirm a sign-in with the AD password succeeds while the old local password fails.

LDAP on port 389 without TLS

Acceptable on an isolated lab subnet, but credentials cross the network unencrypted. Production would issue a certificate to the DC through AD Certificate Services and use LDAPS on 636.

No mail server

Email alerts and activation links can't be delivered (they appear as "Mailer Error" in the system log). Accounts are created by agents with activation emails turned off. Adding an SMTP relay would enable notifications and email-to-ticket.

HTTP only

The portal runs on port 80. A TLS certificate on Apache would be required before any real use.
